## 关键教训

1. **PWA 版本发布铁律**：改前端文件必须同步 APP_VER + SW CACHE 名，否则手机收不到更新
2. **HTML 资源不带 `?v=`**：SW SHELL 存无查询串路径，带查询串请求会 cache miss → 弱网必崩
3. **SW 更新检测必须独立于 app.js**（放 index.html 内联脚本），否则 app.js 崩溃即死锁
4. **只记"认识"不记"遗忘"是统计大坑**：SRS 统计必须双方向记录

## 完全离线包 — SW v71 / APP_VER 20260801b

**重大 BUG 修复**：`createObjectStore("blobs")` 无 keyPath，`put({url,blob})` 无 key 抛 DataError 被吞 → **音频从未真正写入 IDB**。IDB_AUDIO_VER 1→2 重建 store 带 `keyPath:"url"`，音频缓存从此真实生效。

**新功能**（首页「离线包」按钮 + 三档弹层）：
- `precacheBooks`：9 本词书 JS 预缓存进 SW 主 CACHE（cache.match 查缺 add，与 loadBook 同 URL `file?v=APP_VER`）
- `collectAudioUrls`：normJs 全词去重（14,259 唯一词）→ 双口音 URL 去重（uk==us 合并）≈21,600 个
- `downloadAudioList`：并发 3，idbAudioGet 命中跳过（无状态断点续传），fetchAudio(blob, stored) 透传写库结果
- 三档：full(双口音 ~350-650MB) / us(仅美音) / books(仅词库 ~12MB)
- `playAudio` 改用 `audioUrlFor` 三级取 URL（state.cache → EN_DEFS → genAudioUrl）
- `storage.estimate()` 容量预检 + confirm 提示；`offlinePkg` 持久标记 + SW 升级后 `autoReprecacheBooks` 自动补词库
- `offlinePkg.cancel` 取消机制

**经验**：IndexedDB object store 必须设 keyPath 或显式传 key，否则 put 静默失败（try/catch 吞 DataError）——这种"假缓存" bug 极难发现。

## 离线包失败率70%修复 — SW v72 / APP_VER 20260801c

**根因**：`collectAudioUrls` 用 `genAudioUrl` 猜测 URL（`{word}-{accent}.mp3`），但 dictionaryapi.dev 只对词典里有录音的词返回 200，无音频词返回 502 → 70% 失败、fail 是 done 的 2-3 倍。

**修复**：
- 只收集 en_defs 真实 URL（8,291 us + 8,291 uk，重叠 6,925 → 去重 9,657 个），去掉猜测
- `downloadAudioList` 失败重试 1 次（800ms）+ 每请求 80ms 间隔防限流
- 无音频词（~5,852）播放走 TTS 兜底（speak）
- 下载量 ~21600→9657 个 URL（~150-200MB），成功率 95%+
