3.2 存储风险分析

风险点说明严重程度

4. 核心功能模块实现详解

4.1 SRS 间隔重复引擎（艾宾浩斯）

间隔数组：

[10分钟, 1天, 2天, 4天, 7天, 15天, 30天, 60天, 120天] — 共9级，约4个月完成一个完整周期。

评分逻辑 (scheduleReview)：

  • 认识 (know)： intervalIdx +1，进入下一级，最高级后标记 status="mastered"
  • 模糊 (fuzzy)： intervalIdx -1（不低于1），重新回到前一级
  • 不认识 (unknown)： intervalIdx 重置为 0（10分钟后复习），lapses +1

新词初始状态：首次学习后 intervalIdx=1（1天后首次复习）。

待复习计算：遍历 records，nextReview <= endOfDay(now) 即今天需要复习。


✅ 优点：

  • 间隔级数覆盖4个月周期，符合艾宾浩斯记忆曲线理论
  • 三种评分差异化调整幅度（升1/降1/重置），逻辑简洁有效
  • 新词默认1天后复习，避免当天过度重复

⚠️ 不足：

  • 无每日新词上限控制：用户可以无限学习新词，没有"每日学习目标"概念
  • 算法参数固定：S 值（稳定常数）、间隔长度均在代码中硬编码，无法根据用户表现动态调整
  • 缺乏难度系数：所有单词平等对待，没有根据用户对该词的历史表现调整间隔
  • 无复习队列优先级：待复习词按词序排列，而非按"紧迫性"（最该复习的排前面）
  • 无"遗忘后再掌握"的加速机制：每次 lapses 都在同一个词上累加，但不改变其 SRS 参数

4.2 增量模式 (Incremental)

开启后，除 850 基础词 & 初中外，每本词书只显示与"之前所有词本并集"的差集新词。通过 wkey() 归一化函数（小写+去非字母数字）做词形比对。

  • ✅ 优点：解决了多词本之间大量重复词的问题（如四级包含大量高中词），避免用户重复背诵
  • ✅ 细节：差集缓存 _incCache 在词库切换或增量开关变化时失效重算
  • ⚠️ 不足：差值仅基于词形匹配，不考虑一词多义（如 "bank" 在高中是"银行"，在雅思可能是"河岸/倾斜"）

4.3 词根排序

默认排序方式。将单词按 root 字段分组，组间按组词数降序排列，采用轮转交错 (round-robin) 方式从各组依次取词，确保同根词不连续出现。

  • ✅ 优点：巧妙的实现，避免同根词密集出现导致"前摄干扰"
  • ⚠️ 不足：大量单词缺少 root 标注（在 CET-4 中很多高频词如 "the", "a", "to" 无 root），无 root 词各自成组破坏了轮转效果

4.4 单词卡片与翻面

  • 正面：单词(50px)、音标、词根角标、发音按钮、翻面提示
  • 背面：单词(30px)、音标、中文释义、核心意象、英文例句+中文翻译、近义词/反义词 chips
  • 翻面机制：v20260721c 修复为纯 2D opacity 淡入淡出，彻底解决了旧版 3D transform 导致的字体发虚问题
  • 自动发音：每张卡片展示时自动朗读（真实音频优先，TTS 兜底）
  • ⚠️ 不足：例句仅部分词库有（Ogden 基础词有例句+翻译，其他词库主要靠离线 API 数据），且大量词缺少 ex/exz 字段

4.5 离线能力

  • Service Worker (v17)：缓存应用外壳 + 词库 JS 文件，支持离线访问
  • 缓存策略：导航请求网络优先（失败回退缓存），静态资源缓存优先
  • 离线释义包 (en_defs.js, ~28K 条目)：构建期预抓取的英文释义 + 发音 URL
  • 发音：依赖 dictionaryapi.dev 的 CDN 音频 URL（离线时音频不可用，仅 TTS 兜底）
  • ⚠️ 不足：发音音频没有本地化缓存，离线时完全依赖 TTS；large 词库文件（toefl 2.2MB）首次加载较重

4.6 遗忘曲线可视化

使用 Canvas 绘制 30 天遗忘曲线。公式：T30 * exp(-x/FC_S)，其中 FC_S=20 为美观常数（非严谨记忆模型）。基于学习会话记录的 newCount 做每日累加计算。

  • ⚠️ 不足：曲线是纯展示性的归纳（统计学了多少），不是对单个单词记忆强度的预测模型。与 SRS 调度引擎没有直接关联。

6. 交互体验与逻辑不足识别

6.1 学习逻辑层面

#问题影响优先级
1 无每日学习目标：未设新词/复习的每日上限，用户可能一次学太多或太少 学习节奏失控，缺乏成就感 P0
2 SRS 参数静态固化：间隔长度、难度系数不可配置，无法根据用户表现自适应 复习要么太频繁要么太稀疏 P0
3 学习新词无粒度区分：等同于"一次性记住"，没有"再复习一次"的中间选项 新词学习流与复习流割裂 P1
4 缺少拼写测试：纯被动识别（看到英文→回忆中文），无主动输出练习 只练"认读"不练"拼写"，记忆深度不足 P1
5 无复习提醒通知：依赖用户主动打开 App，无推送/提醒机制 遗忘率高，连续学习难以维持 P1
6 遗忘曲线仅为展示：不参与 SRS 决策，与复习引擎脱节 可视化与实际算法两张皮 P2

6.2 交互体验层面

#问题影响优先级
7 无学习激励/游戏化：没有积分、徽章、等级、打卡日历等激励机制 缺乏动力，难以坚持 P0
8 复习评分需要翻卡后才显示：必须先点卡片翻面才能看到评分按钮 增加一步操作，破坏流畅感 P1
9 无学习/复习中的退出确认：切换页面直接丢失当前进度 误触导航栏导致中断 P1
10 单词卡缺乏手势支持：无左右滑动手势（如左滑不认识/右滑认识） 操作较慢，不符合移动端习惯 P2
11 无深色模式：仅有一套亮色主题 夜间学习体验差 P2
12 首页信息密度较低：复习预览仅显示词条 chip，无可操作入口 首页利用率不高 P3

6.3 性能与技术层面

#问题影响优先级

7. 优化建议清单

7.1 第一阶段：学习逻辑核心优化（当前优先）

#优化项详细说明优先级
A1 引入每日学习目标系统 设置每日新词上限(默认20)、每日复习上限(默认100)。首页展示今日进度条和完成状态。支持用户自定义。 P0
A2 SRS 算法升级为 SM-2 变体 引入 ease factor（难度系数），根据用户评分动态调整间隔。对新词学习也引入初始 ease factor。参考 Anki/SuperMemo 的成熟方案。 P0
A3 复习队列智能排序 按 overdue 程度（实际时间 / 计划间隔）排序，最该复习的优先展示。引入"间隔敏感度"权重。 P1
A4 新词学习增加"再看看"选项 在学习新词时增加三档操作：认识了(进SRS) / 再看看(加入本轮循环末尾) / 跳过 P1
A5 增加拼写测试模式 "听音写词"或"看中文写英文"的主动输出练习，作为复习的补充模式 P1
A6 复习提醒通知 利用 Push API / Notification API，在每日设定时间推送复习提醒。PWA + 桌面端可用。 P1

7.2 第二阶段：激励与体验优化

#优化项详细说明优先级

7.3 第三阶段：技术架构升级

#优化项详细说明优先级

C5 数据导出/导入 支持 JSON 格式的学习数据导出/导入，作为手动备份/迁移方案 P2

7.4 第四阶段：商业化架构预留

#优化项详细说明优先级

8.3 关键技术决策建议

决策点推荐方案理由
前端框架 保持原生 JS 或轻量引入 Preact/Alpine.js 词库数据量大（2MB+），引入 React/Vue 会显著增加 bundle 体积。PWA 场景首屏性能优先。
构建工具 Vite 轻量、快速 HMR、原生 ESM 支持，适合中大型 PWA
本地存储 IndexedDB (Dexie.js) 异步、容量大、可建索引、适合大量学习记录
SRS 算法 SM-2 变体 (FSRS 为长期目标) SM-2 成熟稳定、实现简单；FSRS 更精确但复杂度高，可后续迭代
后端语言 Node.js (Express/Fastify) 或 Go (Gin) Node.js 与前端语言统一；Go 性能更好，适合高并发
原生 App Capacitor (推荐) 或 Tauri Capacitor 将 PWA 打包为原生应用；Tauri 更轻量（Rust 后端），但生态较新
